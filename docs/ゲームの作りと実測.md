`.claude/rules/` の `board-games.md`・`card-games.md`・`party-games.md` が目安の大きさ（1ファイル約32,000バイト）を超えたため、
決まりではないもの（実装のメモ・CPU の考え方・CPU どうしの対局の実測）をここへ移した（Claude の推奨を本人が承認）。決まりと壊しやすい所は rules に残してある。

- **このファイルには書き足さない。** 新しい実装のメモ・実測はコミットのメッセージに書く（コードの中身を写した書類は作らない・更新しない、という共通の決まりのため）。
- 書いてあるのは移した時点の作り。**コードが正**なので、食い違っていたらコードを信じる（ここを直しに行かない）。
- 中身は移す前の文をそのまま写した。決まりの部分と重なる文が少しある。
- 「（整理前の全文）」は、rules の側では決まりと理由だけの短い形にした項目の、整理前の文そのもの（パーティーゲームの長い項目）。決まりは rules の短い形が正。

## 盤のゲーム（board-games.md から）

### マルバツ

- 2人の広い盤（22回目の案）の実測:
  CPU どうし（先手を入れ替えて200局）で、5×5 は つよい どうしの半分が引き分け、6×6 より広いと引き分けはほぼ無い（つよい どうしは先手がいつも勝つ。もう一回で先手と後手が入れ替わる）。
  6×6 で ふつう 対 よわい 184勝16敗・つよい 対 ふつう 149勝48敗（`tools/test-cpu.mjs` で毎回見ている）。よわい はかなり弱いので、本人が遊んで弱すぎたら直す。
- かぶせマルバツ（`tictactoe.js` の `gob`）: 選んでいる駒はこの端末だけの `gobSel`（手の一覧に入れない）。CPU は `boardCpu`（よわい1手・ふつう2手・つよい3手、
  適当に打つ割合 4割・1割強・0）。20局ずつで つよい 対 よわい・ふつう 対 よわい とも 20勝0敗（よわいが弱すぎたら直す）。

### コネクトフォー

- じゃま石（`connect4.js`）: 置き場所は対局の種（seed）から決める。そのため**盤のゲームの `init` に `seed` を渡すようにした**（`main.js` の `replay`。
  同じ画面の2人も始めるたび・もう一回のたびに種を作り直す）。じゃま石は `NEUTRAL`（-1）。CPU の点数と3人以上の CPU は、じゃま石を含む並びを数えない。
  じゃま石ありで 60局: 2人 ふつう 対 よわい 50勝10敗・つよい 対 ふつう 40勝16敗、3人 ふつう1人 対 よわい2人 42勝17敗。
- 2人の広い盤（`connect4.js`。2026-10-06 の7回目）: 列の並び（CPU が良い手から調べる順）は `centerOrder`、真ん中の列の点は偶数の幅なら2列。
  CPU の読む深さは列が多いほど浅い（`twoDepth`。7列は前と同じ・8〜9列 つよい5・10〜11列 ふつう3 つよい4）。20局ずつで どの盤も ふつう 対 よわい 15〜18勝・
  つよい 対 ふつう 16〜20勝、1手は最大0.2秒ほど。じゃま石は 7列なら3個、広い盤は列の数の半分（2人でも）。

### リバーシ

- 盤の大きさ: 10×10 の つよい は1手に最大 0.7秒ほど考える（PC で測った。スマホでは もう少しかかる）。
- 四隅封印（`reversi.js`）: 2〜4人・どの盤の大きさでも使える。3〜4人は隅を残して埋まったら終わり。隅を封じると隅のとなりの辺のマスが裏返らなくなるので、
  CPU の石の点はそこを隅の代わりに高くした（`weightOf` の shut）。12局ずつで つよい 対 よわい 12勝0敗・ふつう 対 よわい 8勝4敗。
- 穴あき盤（`reversi.js`。2026-10-06 の5回目）: 穴は 6×6 で2つ・8×8 で4つ・10×10 で6つ。盤の真ん中を中心に**点対称**に置く（先手と後手で不公平にならないように）。
  隅と真ん中の 4×4 には置かない。置き場所は対局の種から（`makeHoles`。じゃま石と同じく `init` の `seed`）。置けないマスは四隅封印の隅と合わせて
  局面の `closed`（Set）にまとめ、`flipsFor` などはそれを見る（前は四隅封印の true/false を渡していた）。CPU の石の点は穴を気にしない。
  穴あり 30局: ふつう 対 よわい 26勝4敗・つよい 対 ふつう 27勝3敗。
- 角でもう1手（16回目の案）:
  手の一覧の形は今のまま（`turn` が同じ人を続けて返すだけ。局面の `bonus`・`again`・`missed`）。CPU は今の点の付け方のまま（隅の点が高いので自然に角を取りに行く）。
  1局で平均3.5回ほど起きる。2人 8×8 で つよい 対 よわい 19勝0敗1分・ふつう 対 よわい 25勝5敗・つよい 対 ふつう 17勝3敗（6×6・10×10 もほぼ同じ差）、
  3〜4人で つよい1人 対 よわい の勝ちが 3人 7割ほど・4人 5割強（なしより差が広がる。`tools/test-cpu.mjs` で毎回見ている）。
  main.js は変えていない。待った（打った人を局面から当て直して数える）・ふりかえり・考えた時間（手ごとに番の人を記録）・CPU の予約（手の数が鍵）は、同じ人が続けて打っても困らない。
  勝敗予想は「打った手の数が人数になるまで」なので、最初の1巡で角が取られると少し早く締め切られる（最初の1巡で角は取れないので、実際はまず起きない）。
- 石の数を隠す（`reversi.js`。19回目の案）: 局面には、ありのときだけ `hide: true` を足す（なしの局面は前と全く同じ）。数を出すのは `info` だけなので、そこで `hide && !over` なら数の代わりに一言を出す。
  ふりかえりの途中の局面は終わっていないので、数は隠れたまま（最後まで進めると、いつもの終わりの画面で出る）。`style.css` は変えていない（一言も `rv-score` のまま）。

### 五目並べ

- 五目並べ（細かい決めごとは `gomoku.js` の先頭）: 最初は禁じ手なし・6つ以上並んでも勝ち（禁じ手は詳細設定。上の「禁じ手」）。盤は詳細設定で 15路（最初）か 13路（スマホで押しやすい）。
  CPU は読みをせず、置いた点の攻めと守りの形の点数で選ぶ。つよいだけ、相手に止められない形を作らせない手を選ぶ（1手先読み）。
  強さの数字は CPU どうしの対局で決めた（80局で ふつう 対 よわい ≒ 60勝18敗、つよい 対 ふつう ≒ 37勝21敗・残りは引き分け）。
- ぴったり五目（`gomoku.js`）: 両者とも同じ（連珠の黒だけの禁じ手とは違う）。CPU は勝てない6つを作る点を0にした。
- はさみ取り（`gomoku.js`）: CPU は取れる組・取られる組を点数に足し、取られる形へ置くのを嫌う。**つよい の1手先読みは「相手に石を取られない手」も条件にしている**
  （入れないと つよい が ふつう に 25勝55敗と負け越した。入れて 80局で 58勝22敗。ふつう 対 よわい は 46勝34敗）。置く処理は CPU の先読みと共通の `place`。
- じゃま石（17回目の案）:
  局面の `grid` で -1（`BLOCK`）。なしのときは局面も乱数の使い方も前と全く同じ。待った・ふりかえりは種から当て直すので、じゃま石も同じ場所に出る。見た目は `gomoku.js` の中で付けた（`style.css` は変えていない）。
  CPU は今の点の付け方のまま（じゃま石は相手の石と同じく並びを切る）。ただし「石の近く」はじゃま石を数えない（数えると、最初の1手がじゃま石のとなりになる）。
  100局で 15路 ふつう 対 よわい 75勝20敗・つよい 対 ふつう 41勝26敗（33局引き分け）、13路 75勝15敗・31勝10敗（59局引き分け）。なしとほぼ同じ差（`tools/test-cpu.mjs` で毎回見ている）。

### 点と線

- 点と線（細かい決めごとは `dots.js` の先頭）: 詳細設定「人数」（2〜4人）と「盤」（四角 3×3〜6×6。おまかせは 2人 4×4・3人 5×5・4人 6×6）。
  同じ数で並んだら引き分け。CPU は、取れる四角を取る・3辺目を引かない・仕方なければ渡す四角が少ない線。
  つよいは2人のときだけ「最後の2つを譲る」終盤の手を使う（3人以上では譲った先の次の人が得をするため使わない。だから3人以上ではふつうとほぼ同じ強さ）。
- 四角を取っても交代（`dots.js`）: CPU は「次の人がすぐ取れる四角の数」だけで線を選ぶ。つよいの「最後の2つを譲る」は使わない（続けて引けないため意味がない）。
- 金の四角（`dots.js`。10回目の案）: 置き場所は対局の種から（`makeGold`。じゃま石と同じく `init` の `seed`）。局面の `gold`（四角の番号の一覧。なしのときは持たない）。
  点は `scoresOf`（金は2点）で数え、状態の欄の数も点。CPU は渡す四角の数を点で数え（金は2）、ふつう以上は取れる四角に金があれば先に取る（よわいは気にしない）。
  100局で ふつう 対 よわい 89勝9敗・つよい 対 ふつう 78勝17敗。取った金の四角はその人の色に金のふちと ★。

### マンカラ

- マンカラ（細かい決めごとは `mancala.js` の先頭）:
  オンラインでは自分の側を下に出す。CPU は `boardCpu` で読む（よわい1手・ふつう3手・つよい6手、適当に打つ割合 3割・1割強・0）。
  60局で ふつう 対 よわい ≒ 58勝1敗、つよい 対 ふつう ≒ 53勝5敗（よわいは人には十分勝てる弱さのつもり。本人が遊んで強すぎ・弱すぎなら直す）。
  3人の CPU は `boardCpu` を使わない（2人用の読みなので、3人では「ふつう」が「よわい」に 2勝58敗と逆になった）。ほかの2人が自分の点（一番多い相手との差）を
  下げにくると考えて読む。読む深さと適当に打つ割合は2人と同じ。90局で 1人 対 同じ強さの2人: ふつう 対 よわい 63勝25敗・つよい 対 よわい 81勝8敗・つよい 対 ふつう 32勝54敗（取り分の3分の1よりやや上）。
- マンカラの石の数を隠す（`mancala.js`。23回目の案）: 局面には、ありのときだけ `hide: true` を足し、`apply` が次の局面へ続ける（なしの局面・画面は前と全く同じ）。
  `render` で `hide && !result` のとき、`.mc-num` を作らない・押せる穴の `aria-label` から数を外す・盤の下の一文に「石の数はひみつ」を足す。`info` はとった数（「（6個）」）を外す。
  石は全部描き、ゴールと13個以上の穴は `.mc-stones.mc-many` に列の数 `--cols` を渡して小さく詰める（`style.css`。2人のゴールは縦長なので列を少なめ、3人の丸いゴールは名前の分だけ1列多め）。
  石は全部で最大108個（3人×穴6つ×6個）なので上限は付けていない（スマホ幅で 62個のゴール・30個の穴でもはみ出さないことを確かめた）。
  ふりかえりの途中の局面は終わっていないので隠れたまま。盤の向き（⇅）・初心者マーク（`button.mc-pit.playable` のまま）はそのまま効く。
- 穴の数（`mancala.js`。10回目の案）: 局面の `holes`（無ければ6）。1人ぶんは「穴 holes 個＋ゴール」で、番号は `pitOf`・`storeOf` で求める（穴6つなら前と全く同じ番号）。
  向かいの穴は `2*holes - i`。詳細設定の鍵は `pits`（リバーシの穴あき盤の鍵 `holes` とぶつからないように）。盤の大きさと同じく好みなので、おまかせでは抽選しない（`main.js` の `KEEP_KEYS`）。
  CPU は今までと同じ読み。60局で 穴4つ ふつう 対 よわい 48〜50勝8〜9敗・つよい 対 ふつう 48〜49勝9〜10敗、穴5つ 55〜56勝2〜5敗・49〜50勝9〜10敗。

### 海戦ゲーム

- 海戦ゲーム（細かい決めごとは `kaisen.js` の先頭）:
  CPU は自分が撃った結果だけを見て選ぶ（相手の配置はのぞかない）。よわいは適当に撃ち当たったあと半分だけまわりを狙う・ふつうは当たったらまわりを狙う・
  つよいはさらに、残っている船が入れる並び方の多いマスを狙う。80局で ふつう 対 よわい ≒ 49勝31敗、つよい 対 ふつう ≒ 66勝14敗。
- ソナー（`kaisen.js`）: 手は `{ t: 'sonar', c: 真ん中のマス }`。局面の `sonar[p]` に `{ c, n, cells: 調べたときにまだ撃っていなかったマス }` を残し、
  CPU は「cells のうち、その後に当たった数」を n から引いて、まだ見つけていない船のマスが残っていればその中を撃ち、残っていなければその中を撃たない。
  CPU は当たりを追っていないときに、6発撃ったあとで使う（よわいは毎回3割の見込み・場所は適当、ふつうはまだ撃っていないマスが多い所、つよいは船が入れる見込みが大きい所）。
  同じ強さで片方だけソナーを使うと、使う方が 300局で 150〜160勝（ほぼ五分。1手使うので、使えば必ず得というほどではない）。
- 海の広さ（`kaisen.js`。2026-10-06 の8回目）: 一辺は局面の `size`（10 か 8）、船の長さは `FLEETS`。マスの番号は「段*一辺+列」で、10×10 の手と結果は前と全く同じ。
  `style.css` の `.ks-grid` は10列の決め打ちなので、列の数は `kaisen.js` が盤ごとに `grid-template-columns` で書き換える。CPU とソナーの使い方（6発撃ったあと）は 10×10 と同じ。
  80局で 8×8 の ふつう 対 よわい ≒ 45勝35敗・つよい 対 ふつう ≒ 59勝21敗（10×10 とほぼ同じ差）。
- 船をくっつけない（`kaisen.js`。12回目の案）: 局面の `apart`。`layout(ships, n, apart)` が並べ終えた盤で別の船どうしのとなり（ななめも）を見て反則にする。
  おまかせ（`randomShips(n, apart)`）は、まわり8マスにほかの船が無い所にだけ置く（並べきれなければ最初からやり直すので必ず並ぶ。なしのときは乱数の使い方も前と同じ）。
  CPU は、船がないと分かるマス（沈めた船のまわり8マス・追っている当たりのななめ・当たりが2つ並んだらその横）を撃ったマスと同じに扱う（`noShipCells`）。
  80局で 10×10 の ふつう 対 よわい ≒ 54勝26敗・つよい 対 ふつう ≒ 68勝12敗、8×8 は 45勝35敗・60勝20敗（なしとほぼ同じ差）。
- サルボ（`kaisen.js`。15回目の案）: 手は `{ t: 'salvo', cells: [マス…], n: 何手目か（局面の count） }`。撃つ数は `salvoCount`（まだ撃っていないマスが船の数より少なければ、その数）。
  数が合わない・重なる・撃ったことのあるマス・n が合わない手は反則（n があるので同じ手が2回届いても2回目は反則）。ありのときは1マスずつの手も反則。
  局面の `salvo`、`again` は init で false にする。`last` は `{ p, salvo: マス, hit, hits: 当たりの数, sunk: 沈めた最初の船, sunks: 沈めた船の一覧 }`。
  選んでいる途中のマスはこの端末だけの `salvoSel`（手の一覧に入れない）。選んだマスは `style.css` に足さず、`kaisen.js` が色と選んだ順の番号を付ける。
  CPU（`salvoCpu`）は撃つ数だけ、いつもの考え方（`kaisenCpu`）で1マスずつ選ぶ。選んだマスは結果が分からないまま撃ったマスと同じに扱う（当たりのまわりは4方向をまとめて狙う）。
  ソナーは1つ目を選ぶときだけ考え、選んだらその番はソナーだけ。200局で 10×10 の ふつう 対 よわい ≒ 131勝69敗・つよい 対 ふつう ≒ 145勝55敗、
  8×8 は 125勝75敗・149勝51敗（なしとほぼ同じ差）。

### はさみ将棋

- はさみ将棋（`hasami.js`）:
  CPU は `boardCpu`（よわい1手・ふつう2手・つよい3手、適当に打つ割合 35%・10%・0）。形勢は取った数の差だけ（動ける数も見ると つよい の1手が PC で2秒を超えた）。
  30局ずつで ふつう 対 よわい 30勝0敗・つよい 対 ふつう 30勝0敗（差が大きいので、本人が遊んで よわい が弱すぎたら直す）。
- はさみ将棋の盤の大きさ（`hasami.js`。11回目の案）: 一辺は局面の `n`（9 か 7）。手は「元 * マスの数 + 先」で、9×9 の手と結果・局面の目印は前と全く同じ
  （目印の乱数の表は 9×9 の大きさのまま作り、7×7 はその前の方を使う）。鍵は `size` で、盤の大きさなので おまかせでは抽選しない（`main.js` の `luckSettings` が size を外す）。
  30局で 7×7 の ふつう 対 よわい 30勝0敗・つよい 対 ふつう 30勝0敗（9×9 と同じく差が大きい）。

## カードゲーム（card-games.md から）

### いろあわせ

- 同じ数字まとめ出し（`colors.js`）: 手は `more`（いっしょに出す札の位置を出す順に）。画面では、同じ数字をほかにも持っていれば押した後に
  手札から順に選ばせ、札に選んだ順の番号を出す。引いた札は1枚だけ・7・0 をまとめても交換と回しは1回。CPU は同じ数字を全部出し、手元に多く残る色を一番上にする。
- 手札の上限の作り（`colors.js`）: 脱落は局面の `out`（席ごとの真偽）。番の進め方は全部 `stepAlive`（脱落した人を飛ばして数える）を通す。
  2人残りのリバースはスキップと同じ・7で交換の相手と0で回すは脱落していない人だけ。引いたあと（自分で引く・ドロー2/4・重ね返しを引き取る・宣言忘れ）に `checkCap` で調べる。
  ふつうの CPU 対局では25枚を超えることはめったにない（120局で1回）ので、自動確認は始めから1人脱落させた局面からも打たせている。
- 最後の1枚の宣言（`colors.js`）: 手の `call: true`。数えるのは出し終わった時点の自分の手札（7で交換・0で回すのあとも）。上がり（0枚）は要らない。
  **宣言ボタンは自分の番の間ずっと出す**（1枚になるときだけ出すと、覚えていなくても気づけてしまうため）。押したかはこの端末だけの `called`
  （出す手に付ける。番が終わると消える）。CPU は1割5分の見込みで忘れる（`cpu` が `cpuMove` の手に付け足す）。
- チャレンジ（9回目の案）:
  作り（`colors.js`）: 返事を待つ間は重ね返しと同じ `s.pend` に `ch`（出した人・出す前の色・うそか）を付ける。うそかは `apply` の中で出す前の局面から求める。
  手は `{ t: 'challenge' }`（`ch` が無ければ反則なので、2回届いても2回目は弾く）。受けるは今までの `draw`。引いたあとは今の手札の上限の決まり（`checkCap`）を通す。
