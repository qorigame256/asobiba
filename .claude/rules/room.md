ゲームのファイルにもかかわる作り（おまかせ・盤の向き・CPU の名前・初心者マーク など）と壊しやすい所は CLAUDE.md にある。
**部屋の機能について本人が新しく決めたことと新しい注意は、ここに書く**（CLAUDE.md には機能の名前も足さない。2026-11-09 から。前は名前だけを CLAUDE.md に足していた。Claude の推奨を本人が承認）。

コミットのメッセージに書き、ここにも docs にも足さない**（分かれ目は 2026-11-08、作りの説明は 2026-10-27 から。ゲームの rules と同じ形。Claude の推奨を本人が承認）。

## 壊しやすい所（コードを読んでも分からない注意）

- エアホッケー（`live: true`）は手の一覧を使わない別の形（`index.js` 先頭のコメント）。`main.js` の `renderLive` が対局ごとに1回だけ
  `mount` し、届いた `type: 'live'` の中身をそのまま渡す（描き直さない）。`replay` は live のゲームを当て直さず `{}` を返す
  （これが無いとゲストが部屋の状態を受け取れず待合室から進まなかった）。`hockey.js` 側の注意は `hockey.md` の「壊しやすい所・確かめ方」。
- エアホッケーは結果も CPU も画面の描き方も `main.js` を通らない（`hockey.js` が持つ。2026-11-05 に足した紙相撲 `sumo.js` も同じ）ので、勝ち残り・CPU の強さの自動合わせ・対局の時間・観戦の人数・あいさつ・
  紙吹雪・先手のくじ・途中から空いた席に入る は出ない。
- 対局は `gameId`・`round`・`seed` の組で見分ける。同じ画面の対局は「もう一回」で `round` を変えず `seed` だけ作り直すので、`round` だけでは前の対局と区別できない
  （ふりかえり・同じ画面の成績・始めのあいさつ・対局の時間がこの組で見ている）。
- 途中から空いた席に入る（`takeSeat`）は `round` を進めない。CLAUDE.md の「`order` や `seed` を変えるときは必ず `round` を進める」の例外（局面もプレイヤー番号もそのままで
  人が替わるだけなので、当て直しても同じ）。予約してあった CPU の手は、打つときに席が人に替わったのを見て止まる（`scheduleCpu`）。
- `cpuControlled` は、部屋を出た人に加えて、対局の途中で待合室へ行った人（`S.away`）の席も CPU が打つと見る。
- 観戦の人が選んだ人の手元は、ゲームの `me` に席の番号を渡して見せているだけ（`watchSeat`）。打てるかは `canMove` が `myPlayer()` で見るので観戦の人は打てない。
  **`canMove` を `me` で見るように変えないこと**（観戦の人が打ててしまう）。
- ふりかえりはカードゲーム（`multi`）に出さない（伏せた札が見えてしまう）。
- 部屋の数（連勝・成績表・履歴・予想の当たり・最高記録・点）は、ホストの `countResult` が対局ごとに1回だけ数え、`state` で全員へ送る（あとから入った人にも同じ数が見えるように）。
  成績表（`S.tally`）は人の id だけで数える（CPU の番号 `cpu1` などは対局ごとに付け直すため。履歴は勝った人をそのときの表示名で覚える）。
- 入り直しの引き継ぎ（`acceptMember` → `replaceMember`）は、端末の印（localStorage の `bg-dev`）が同じうえに、名前も同じか前の人の合図が途切れているときだけ。
  同じブラウザの別のタブは印が同じなので、1台で2人分を確かめるときは名前を変えて入る（同じ名前だと前のタブが部屋を出される）。
- 部屋の人から届いた値は外から来た値として扱う（公開の中継サーバーのため）。数は整数か確かめ、選ぶもの（マーク・ゲームの id・じゃんけんの手）は
  一覧（`MARKS`・`GAMES`・`RPS`）にあるときだけ使い、文字は `esc()` か `textContent` を通す。送りっぱなしの合図のうち `award`・`lot`・`drawn` は
  ホスト（`S.members[0]`）からのものだけ受け付ける。
- `setUrlRoom` は `history.state` を残すこと（消すと、うっかり閉じない確認の受け皿が再読み込みのたびに増えた）。
- 決着したときに出す一言（自己ベスト・CPU 図鑑・色の解放）は `lateToast` で出す（すぐ出すと、決着のあいさつの一言に上書きされて見えない）。
- 光る・降る動き（準備OK の「始める」・紙吹雪）は、動きを減らす設定（`prefers-reduced-motion`）の端末では出さない。
- MIT の道具や一覧を足したら `LICENSES`（お問い合わせ・通報・ライセンスの小窓）にも足す。作者の表示が要る素材（CC BY 4.0 の OtoLogic の効果音など）を別の作者から足したときも同じ。
  OtoLogic の音を全部ほかの音に替えたら、`LICENSES` の OtoLogic の行を消す。
- 音のファイルは片耳・22050Hz の WAV にする（素材の ogg は iPhone の Safari で鳴らないことがある）。
  **音を足す・替えるときは `tools/level-sound.mjs` で役割ごとの目標の大きさにそろえてから置く**（2026-10-31 から。`sound.js` は全部の音に同じ倍率を掛けるだけで、音ごとに下げる表はもう無い。
  素材をそのまま置くと、ほかの音より 10dB 以上大きく・小さく鳴る。今の音のつり合いは本人が試聴ページで聞いて承認したもの）。
- 声のファイル（`app/voice/<hau|bee>/*.mp3`。2026-11-08）は、上の「WAV にする」の例外で mp3 にしている（2人 × 約170個あり、WAV では数 MB になるため。mp3 は iPhone の Safari でも鳴る）。
  名前は言葉から作る（`sound.js` の `voiceId`）ので、決まった言葉（あいさつ・ビンゴの読み・かるたの読み・旗揚げのお題の部品 など）を変えたら `node tools/make-voice.mjs` で作り直す（作り直さないと、その言葉はブラウザの読み上げに戻る。`tools/test-logic.mjs` が落ちて知らせる）。
  声のファイルは mp3 のまま覚えて鳴らすたびに直している（直したものを全部持つと数十 MB になるため）。
- 読み上げ（`sound.js`）で、最初に触れたときに音を0にした「あ」を読むのは iPhone で読み上げを使えるようにするため、読み上げ中の文を `held` に持っておくのは
  Chrome で読み上げが詰まらないようにするため（どちらも消さない）。
- 自分のマーク（`MARKS`）に CPU の 🤖 と初心者マークの 🔰 を入れない。ホームのボタン「📖 図鑑」を「CPU 図鑑」にしない（スマホ幅で2行に割れた）。
- 順番の帯で、ゲームから抜けた人を薄くするのはしていない（抜けた人を知る共通の約束がゲームに無いため）。
- 裏に回って3秒より長くたってから戻ったら、つなぎ方（`S.net`）を作り直す（`main.js` の `HIDDEN_RECONNECT_MS`。iPhone は裏で通信を黙って止め、mqtt.js は keepalive が切れるまで気づかない）。
  **作り直すときに `S.conn` を 'connecting' にしない**（戻るたびに赤い帯が一瞬出る）。抜けたと見るまでの `LOST_MS` は 2026-10-30 に20秒から40秒へ延ばした（少し裏に回っただけで席が CPU に替わらないように）。
  **つながったときゲストが手の一覧も送り直すのを消さない**（`onConn`。作り直すと、古いつなぎ方でまだ届いていなかった手が一緒に捨てられるため）。
- 押したボタンの位置がずれないようにするときは `keepPlace(鍵, 描き直し)` と、ボタンの `data-keep` を使う（待合室の「CPU を増やす・減らす」。2026-10-30 本人の依頼）。描き直しが終わってから測るので、描き直しの途中で長さを測らない決まりには当たらない。
