# 部屋と対局画面の機能の作り

どのゲームでも使う部屋・待合室・対局画面の機能のうち、`main.js` の中で完結する作り（2026-10-11 に CLAUDE.md の「Claude が決めた作り」から移した。
CLAUDE.md が目安の大きさを超えたため。Claude の推奨を本人が承認）。何を作るかの本人の決定は CLAUDE.md の「本人が決めたこと」、
ゲームのファイルにもかかわる作り（効果音・おまかせ・盤の向き・CPU の名前・初心者マーク など）と壊しやすい所は CLAUDE.md にある。
**新しい部屋の機能の作りは、ここに書く。**

## Claude が決めた作り（本人に説明済み・変えるなら本人に確認）

- 勝ち残りの作り（`main.js` の「勝ち残り」の節）: 部屋の設定（`S.stay`。ゲームを変えても残る）で、交代を待つ人の順番（`S.line`）と一緒に `state` で全員へ送る（結果の画面に「次は ○○ が入ります」を出すため）。
  負けた人の席に、前から待っている人 → 負けた人の順で入れ、新しく入った人から先に打つ。待っている人がいなければ負けた人が続ける。負けた CPU は待っている人がいれば抜ける。
  引き分け・待っている人がいないときは、いつものもう一回（打つ順番を1つ回す）。部屋を出た人の席も埋める。エアホッケーは結果が `main.js` を通らないので出さない。
  勝ち残りの間は、連勝を顔ぶれでなくゲームだけで見る（`streakKey`。顔ぶれが毎回変わっても勝ち続けた人の連勝が続くように）。
- 連勝の作り（`main.js` の「連勝」の節）: ホストの端末だけが、対局の結果を見たときに1回だけ数え（`S.streak.counted`）、`state` の `streak` で全員へ送る
  （あとから入った人にも同じ数が見えるように）。顔ぶれは `order` の人の id を並べ替えたもので見るので、ゲームを変える・人や CPU の数が変わると数え直す。
  引き分けは全員の連勝が止まる。勝った人が2人以上（同点の1位・チームの勝ち）なら全員を数える。勝った人は結果の `winners`、無ければ `winner` で見る。
  盤のゲームで CPU が2人以上いると、もう一回で CPU の番号（cpu1・cpu2）が席と一緒に入れ替わるので、CPU どうしの連勝が入れ替わって見えることがある（人の連勝は正しい）。
- 部屋の成績表の作り（`main.js` の「部屋の成績表」の節）: 連勝と同じ所（`countResult`。ホストだけ・対局ごとに1回）で `S.tally`（{ games, wins: 人の id → 勝った回数 }）を数え、
  `state` の `tally` で全員へ送る。**人だけを数える**（CPU の番号は対局ごとに付け直すので）。引き分けはだれも勝ちにしない。部屋にいる人は0勝でも出し、出た人は勝ちがあれば出す。
  届いた数は整数だけ使う（外から来た値なので、そのまま HTML に入れない）。
- 番の知らせの作り（`main.js` の「番が来たらタブの名前で知らせる」の節）: 描き直しのたびに `S.myTurnNow` を決め、`render` の最後に `document.title` を替える。
  付けるのは「番が来た」音と同じく番が決まるゲームだけ（全員が同時に動く `realtime` のゲーム・カードゲームで `turn` が自分でない場面は付けない）。部屋を出る・退出させられたら元に戻す。
- 自分のマークの作り（`main.js` の「自分のマーク」の節）: 選べるのは `MARKS` の一覧だけ（外から来た値は一覧にあるときだけ使う）。CPU の 🤖・初心者マークの 🔰 は入れない。
  localStorage の `bg-mark`。ゲストは `hello` の `mark` で知らせ、ホストが `S.marks` に集めて `state` で送る（初心者マークと同じ形）。`nameOf` が名前の前に付けるので、ゲームに渡す名前にも付く。
  ホーム画面でしか変えられない（部屋の中で変えても、次に入ったときに届く）。
- 対局の時間の作り（`main.js` の「対局の時間」の節）: ホストの端末（同じ画面の対局ではその端末）が、対局の画面を最初に描いたときから決着を見たときまでを測り、
  `state` の `timer`（{ key: ゲーム・回・種, start, end }）で全員へ送る（始めと終わりを同じ端末の時計で測るため）。途中から測り始めたときは出さない。エアホッケーは出ない。
- お気に入りの作り（`main.js` の「お気に入り」の節）: localStorage の `bg-favs`（ゲームの id の一覧）。`gameOrder()` がいつもの並びのまま、お気に入りを先頭へ寄せる。部屋の人には送らない。
- 対局の履歴の作り（`main.js` の「対局の履歴」の節）: 成績表と同じ所（`countResult`）でホストが `S.history`（{ g: ゲーム, w: 勝った人の表示名の一覧 }。新しい順に `HISTORY_MAX` 個）に足し、
  `state` の `history` で送る。勝った人はそのときの表示名で覚える（CPU の名前は対局ごとに変わるため）。外から来た名前なので、出すときは `esc()` を通す。
- 招待の QR コードの作り（`main.js` の `invite`）: QR コードを作る道具 qrcode-generator（MIT ライセンス）を mqtt.js と同じく unpkg から版を固定して（1.4.4）、初めて小窓を開いたときだけ読む。
  黒いマスを1本の path にした SVG で描く。読めないとき（電波が悪いなど）は QR コードの代わりに一言出し、部屋コードとリンクを送るボタンだけにする。
- 準備OK の作り（`main.js` の「準備OK」の節）: 押せるのはホスト以外の部屋の人（観戦の人も）。ホストは数えない。押さなくても始められる（目安だけ）。
  ゲストは `type: 'ready'`（`round` 付き）を送り、ホストが `S.ready`（{ round, ids }）に集めて `state` で送る。`round` が進む（ゲームを変える・対局を始める）と前の準備OK は消える。
  全員そろったら、ホストの画面に一言（toast）を出し、「始める」に `ready-go`（光る。動きを減らす設定の端末では光らせない）を付ける。
- 次のゲームの投票の作り（`main.js` の「次のゲームの投票」の節）: 投票するのはホスト以外（ホストは決める人なので）。ゲストの待合室の下の段に「🗳 次に遊びたいゲーム」の一覧
  （いまのゲームは出さない。「えらばない」で取り消せる）。ゲストは `type: 'vote'` を送り、ホストが `S.votes`（人の id → ゲームの id）に集めて `state` で送る。
  部屋を出た人の票は数えない。**そのゲームに切り替えたら、そのゲームへの票は消す**（`newRound`。ほかのゲームへの票は残る）。外から来たゲームの id は `GAMES` にあるものだけ使う。
- いまのルールの作り（`main.js` の「いまのルール」の節・`renderHowto`）: `changedRules` が詳細設定の最初の値（`def`）と違う項目を「名前: 選んだもの」で並べる。
  遊び方の欄の中身は、ゲームか変えたルールが変わったときだけ作り直す（ルールだけ変わったときは開いたまま）。詳細設定の無いゲームには出さない。
- 部屋の名前の作り（`main.js` の「部屋の名前」の節）: `S.roomName`（`cleanRoomName` で空白をまとめて16文字まで）。`state` の `roomName` で送り、受け手も同じように整える。
  外から来た文字なので、部屋の欄は `textContent`、招待の小窓は `esc()` で出す。
- 詳細設定を覚える作り（`main.js` の「詳細設定を覚える」の節）: localStorage の `bg-rules`（ゲームの id → 詳細設定）。ホストが詳細設定を変える・おまかせ・最初に戻すのたびに `rememberRules` で保存し、
  `createRoom` の始めの `rules` に `savedRules()` を入れる。値の正しさは `rulesOf` が見る（おかしな値は最初の値に直る）。同じ画面の対局には使わない（詳細設定を選ぶ所が無いため）。
- CPU の強さを自動で合わせる作り（`main.js` の「CPU の強さを自動で合わせる」の節）: 部屋の設定 `S.cpuAuto`（`state` の `cpuAuto` で送る）。詳細設定「CPU の強さ」（key `cpu`）を持つ盤のゲームだけ（`cpuLevels`）。
  `newRound` の盤のゲームのもう一回で `adjustCpu` が決着を見て、勝った人に人がいて CPU がいなければ1段上げ、逆なら1段下げる（引き分け・人どうし・CPU どうしは変えない）。
  変えた強さは詳細設定に入れて全員へ送り、`rememberRules` で覚える。エアホッケーは結果が `main.js` を通らないので出さない。
- 画面を暗くしないの作り（`main.js` の「画面を暗くしない」の節）: ブラウザの Screen Wake Lock（iPhone は iOS 16.4 から）。`showScreen('play')` でかけ、ほかの画面で外す。
  ほかのタブ・アプリへ移るとブラウザが自動で外すので、戻ってきたとき（`visibilitychange`）にかけ直す。使えない・断られた端末では何もしない。
- 通信の具合の作り（`main.js` の「通信の具合」の節・`net.js` の `onSelf`）: 5秒ごとの生存確認の合図（`ping`）に送った時刻 `t` を入れ、自分に戻ってきたとき（`net.js` は自分の送ったものを
  ふつうの受け取りに回さず `onSelf` へ渡す）の差を遅れ `S.rtt` にする。遅れが1.5秒より長い・合図が12秒より長く戻らない（`S.pingAt`）と黄色。
  切れたときの帯（`#net-banner`）は、一度つながった（`S.everReady`）オンラインの部屋で `S.conn` が ready でない間だけ、対局の画面の先頭に `position: sticky` で出す（上の段を隠さない）。
- 観戦の人数の作り（`main.js` の `watchHtml`）: 部屋にいて、この対局の顔ぶれ（`order`）に入っていない人を数える（自分も入れ、名前は「あなた」）。送るものは足していない（どの端末も部屋の人と `order` を知っている）。
  エアホッケーは状態の欄を描かないので出ない。
- 名前の読み上げ・あいさつの作り（`main.js` の「番が来たら名前を読み上げ・あいさつ」の節・`sound.js` の `speak`）: 声は `speak`（🔇・画面に触れる前は言わない）。
  名前の読み上げは「番が来た」音と同じとき（オンライン・5秒より長く待った）に、音のあとで自分の端末の名前を読む（空なら「あなたの番です」）。音は残した（声の出ない端末のため）。
  始めのあいさつは対局（ゲーム・回・種）ごとに、手がまだ無い局面を初めて描いたときだけ（途中から入った・手のある局面の再読み込みでは出さない）。終わりは決着の手の音のあと（`moveSound`）。
  各自の端末が出す（送らない）。エアホッケーは main.js で描かないので出ない。
- お開きの表彰の作り（`main.js` の「お開きの表彰」の節）: ホストが `type: 'award'` を送りっぱなしにし（ホストからの合図だけ受け付ける）、受け取った端末がそれぞれ自分の成績表（`S.tally`。state で全員同じ）から順位を作る。
  部屋も成績表もそのまま（閉じれば待合室）。成績表に対局が1回でもあるときだけ押せる（成績表の行の「成績を0に戻す」の隣）。勝ち数が同じ人は同じ順位で、次の順位は飛ばす（1位が2人なら次は3位）。
  だれも勝っていなければ「みんな引き分け」。予想の当たりが1回でもあれば「🔮 予想王」を添える。勝ちの音と紙吹雪（動きを減らす設定の端末では紙吹雪なし）。名前は `esc()` を通す。
- 同じ画面の成績の作り（`main.js` の「同じ画面の成績」の節）: 同じ画面の対局は名前が無く、もう一回でも先手と後手が入れ替わらないので、席（○・×、先手・後手など `game.players`）ごとに数える。
  対局ごとに1回（もう一回で作り直す `seed` で見分ける）。`S.localTally` に入れるだけで保存しない。オンラインの成績表と同じ所（状態の欄の `tally`）に出す。
- CPU のひとことの作り（`main.js` の「CPU のひとこと」の節）: 言うかどうかと言葉はホストの端末だけが決め、`type: 'cpusay'`（CPU の id・種類・言葉の番号）を送りっぱなしにする（受け手はホストからの・いまの対局の CPU の分だけ出す）。
  決着: CPU が勝てばその CPU が必ず、人が勝てば CPU の1人が7割、引き分けは5割（CPU が何人いても1つだけ）。途中: CPU が打ったあとに6%の見込みで、部屋の中で25秒に1回まで（決着した手では言わない）。
  言うのは本物の CPU だけ（部屋を出た人の代わりに打っている CPU は言わない）。言葉は `CPU_LINES` だけ（外から来た番号は一覧にあるときだけ使う）。エアホッケーは CPU が main.js を通らないので言わない。
  吹き出しはリアクションと同じ `showBubble`（`.react-bubble.cpu`）。
- 先手をくじで決めるの作り（`main.js` の「先手をくじで決める」の節）: 席の顔ぶれ（`boardPick`）はそのままで、並びだけをまぜて `S.pick` に入れ、いつもの席の選び方と同じく `state` で送る。
  あわせて `type: 'lot'`（まぜた pick 付き）を送りっぱなしにし、受け手はホストからの・待合室の間の・部屋の人か cpu だけの pick のときに一言（toast）を出す。エアホッケーには出さない。
- うっかり閉じない確認の作り（`main.js` の「うっかり閉じない確認」の節）: 部屋に入ると（`enterPlay`）履歴に受け皿を1つ足し（`history.pushState` の `bgGuard`）、「戻る」でそれが消えた（`popstate`）ときに聞く。
  出ないなら足し直す。「部屋を出る」・退出させられたときは受け皿を自分で消す（`dropBack`）。**`setUrlRoom` は `history.state` を残すこと**（消すと再読み込みのたびに受け皿が増えた）。
  タブを閉じる・再読み込みは `beforeunload`（部屋にいる間だけ。文はブラウザが決める）。
- 待合室でじゃんけんの作り（`main.js` の「待合室でじゃんけん」の節）: 部屋の設定 `S.rps`（{ n: 回の番号, hands: 人の id → 'g'|'c'|'p' }）。ゲストは `type: 'rps'`（n と手 h）を送り、ホストが `rpsPut` で入れて `state` の `rps` で送る。
  部屋の人全員（1人なら自分と cpu）の手がそろったら見せる。見せたあとに出すと次の回。見せた直後に同時に出した人（1つ前の n）は次の回に入れる（ブラウザで2人同時に押して確かめた）。
  1人で CPU とした回が残っているところに人が入ってきたら、その回は終わったものとして扱う（`rpsSolo`）。1人のときは出し直せる（相手が抜けて1人になったときに止まらないように）。
  音は手を見せた回ごとに1回（勝った人は「正解」、ほかは pop）。部屋に入ったときにもう見せてあった回では鳴らさない。外から来た手は `RPS` にあるものだけ使う。
- 勝率の作り（`main.js` の `countResult`・`rateText`）: 成績表に `played`（人の id → 対局した回数。`S.order` にいた人。CPU は数えない）を足した。
  前の形の成績表（`played` が無いまま対局がある）は、勝ちの数と合わなくなるので「成績を0に戻す」まで勝率を出さない。
- 予想の当たりの作り（`main.js` の `countResult`）: 成績表を数えるときに、ホストの端末に届いている予想（`predsNow`）から当たった人を `S.tally.preds`（人の id → 回数）に足す。
  予想は1巡までに締め切るので、決着のときには届いている。前の形の成績表（`preds` が無い）もそのまま使える。「成績を0に戻す」で一緒に消える。
- ふりかえりの作り（`main.js` の「対局のふりかえり」の節）: 見ている所は各自の端末だけ（`S.review = { key, k }`。ほかの人と合わせない・保存しない）。
  途中の局面は手の一覧の先頭 k 手を `replay` して作り、押せない形で描く。最後まで進めるといつもの終わりの画面に戻る。**カードゲームには出さない**（伏せた札が見えてしまうため）。
  対局の見分けに `seed` も使う（同じ画面の対局は「もう一回」で `round` が変わらず、`seed` だけ作り直すため）。
- 紙吹雪の作り（`main.js` の `confetti`）: 勝ちの音（`sound.js` の `endSound` が 'win'）を鳴らす画面に出す。そのため観戦の人と同じ画面の対局でも、決着すれば出る。
  動きを減らす設定の端末では出さない。エアホッケーは結果が `main.js` を通らないので出ない。
- 勝敗予想の作り（`main.js` の「勝敗予想」の節）: 選べるのは、打たれた手の数が対局する人数になる（1巡する）まで（時間で進むゲームの進行役の手 p = -1 は数えない）。
  1人1回・変えられない・自分を選んでもよい。`type: 'pred'` で送りっぱなしにし、受け取った端末がそれぞれ `S.preds` に覚える（あとから入った人には届かない。Claude の判断）。
