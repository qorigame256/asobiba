## 石取り

- **石取り**: 自分の番に、山から石を取る。**最後の1個を取った人の負け。** 2〜6人が順番に。詳細設定で「最後を取った人の勝ち」も選べる。
  **山は1つ。1回に取れる最大数は対局の始めに3〜5個から決め、その対局の間はずっと同じ**（2026-10-03 本人の決定。山3つはあとで下の「山の数」に足した）。
- **石取りの表示**（2026-10-04 本人の希望）: 直前の人が取った石を色付きで残す（次の人が取るまで）。
- **石取りの「1回に取れる数」**（2026-10-06 の3回目の案。本人の選択で、Claude は今のままを推した）: 詳細設定で おまかせ（最初。毎回3〜5個のどれか）／3個まで／4個まで／5個まで。
- **石取りの「取った数で勝負」**（2026-10-07 の15回目の案）: 詳細設定「勝ち負け」（最後の1個で負け（最初）／最後の1個で勝ち／取った数で勝負）の3つ目。山がなくなったとき取った石の合計がいちばん多い人の勝ち。
  **鍵と値は前の詳細設定「最後の1個」のまま（`last`・`lose`・`win`）で、足した値は `count`**（前の部屋の設定がそのまま使えるように）。
- **石取りの「残りを隠す」**（2026-10-07 の17回目の案）: 詳細設定で なし（最初）・あり。決着するまで山の残りの数を見せない。
  **取る数のボタンは残りが少なくても減らさず、残りより多い数を選んだら弾かずに残りを全部取る**（減らしたり弾いたりすると残りの数が分かってしまうため。Claude の判断）。
- **石取りの「山の数」**（2026-10-07 の19回目の案）: 詳細設定で 1つ（最初）・3つ。3つでは山は **3・5・7個**（昔からのニム）で、1つの山から1個以上、その山の全部まで取れる。
  残りを隠すと一緒のときは山の大きさを種から変え、空になった山は「なし」と見せる（3・5・7 のままだと残りが分かり、見せないと空の山を選んで番をむだにするため）。

## ウミガメのスープ

- **ウミガメのスープ**: 部屋の1人が出題者（1問ごとに交代）。ほかの人は順番に、自分の番で「質問」か「解答」のどちらか1つ。
  出題者は「はい・いいえ・関係ない」で答え、解答の正誤も決める。外しても続けられ、いちばん先に当てた人の勝ち。
  問題は Claude が作るオリジナル問題集から選ぶか、出題者が書く。**回答者に CPU は入れられない**（質問ができないため）。
- **2026-10-26 本人の依頼**: CPU も出題者になれる（詳細設定「出題者」）・前の はい／いいえ／関係ありません を直せる・各人の考えた時間を出す・出題者を選べる（問題を選ぶ前にほかの人へ代われる）。
  **CPU の出題者は AI ではなく「言葉の手がかりで答える」簡単なもの**（本人の決定。AI はサーバーと費用が要ると伝えて、本人が選んだ）。
- **ウミガメのスープの「質問の数」**（2026-10-06 の6回目の案）: 決めない（最初）・20回・30回。使い切ってだれも当てられなければ出題者の勝ち
  （その前に回答者が1人1回ずつ最後の解答をするのは、最後の質問をした人以外が解答できないまま終わらないように Claude が足した）。
- **ウミガメのスープの「部分的にはい」**（2026-10-07 の21回目の案）: なし・あり（2026-10-26 から最初は あり。本人の依頼）。出題者の答えに「部分的にはい」を足す。
- **ウミガメのスープの「制限時間」**（2026-10-22 の27回目の案）: 決めない（最初）・5分・10分。時間がたったら、質問を使い切ったときと同じく最後の解答に入る。
- **ウミガメのスープの「答えを見る」はほかの回答者にも聞く**（2026-11-03 本人の依頼）: CPU が出題者のとき、回答者のだれかが「答えを見る」を押したら、ほかの回答者に「答えを見ますか？」と聞き、**全員が「はい」を選んだら答えを出す**。
  Claude の判断: だれかが「まだ考える」を選ぶか、押した人が「取り下げる」を押したら取り下げて続ける。回答者が1人のときは今までどおりすぐ出す。部屋を出た人の席は「はい」。結果の文は「答えを見ました（だれも当てられませんでした）」（`umigame.js` の先頭）。

## 壊しやすい所・注意

- ウミガメの入力欄は、描き直しのたびに作り直さない（作り直すとスマホのキーボードが閉じ、打ちかけの文字が消える）。
  同じ場面のうちは入力欄を残して、ほかの所だけ差し替えている。ワードウルフの「みんなのお題」の入力欄も同じ（`wordwolf.js` の `ui`）。人狼の話す欄も同じ（`jinro.js` の `ui`。昼でないときは隠すだけ）。
  以心伝心の入力欄も同じ（打ちかけの文字が消えないように。`ishin.js` の `ui`）。
  お絵描き当ては絵（canvas）も残す（描き直すたびに作り直すと、描いている途中の線が消える）。1回ごとに1度だけ作り、新しい線だけを描き足す（`oekaki.js` の `ui` と `paint`）。
- お絵描き当ての「答える」は、押しても入力欄から外れない形にしてある（スマホでボタンに移るとキーボードが閉じ、まちがえたあと打ち直せなかったため。2026-10-26 本人の声）。
- ビンゴの名前の札は高さと段の数を変えない（`bingo.js` の `cc-steady`。わけと注意は `quick-games.md` の「壊しやすい所」の名前の札の項）。
- ビンゴの「自分で押す」のマスは指が触れた瞬間（`pointerdown`）に押したことにする（`click` を待つと、ほかの人や CPU の手でカードが作り直されたときに押したのが消えた。2026-10-30 本人の報告「押しても反応しないことがあった」）。
- お絵描き当ての線は手の一覧に入り、毎回まるごと送られる。送る量を小さくするため、座標は 0〜999 を2文字ずつに縮め、近すぎる点は捨て、0.5秒ごとにまとめて送っている。
  10人で描きまくっても1対局で数十 KB の見込み（実測はしていない）。区切りを細かくしたり座標を細かくしたりすると、送る量が増える。
- お絵描き当てのインクの長さは整数の座標から `Math.sqrt` で数えて丸める（**`Math.hypot` を使わない**。端末で末尾がずれると同期が崩れるため）。
- 遊び方を足したとき、なし（最初の値）のときの局面の形と乱数の使い方を前と全く同じにしてあり、`tools/test-logic.mjs` が前の作りで取った指紋と比べているものが多い
  （お絵描き当て・ヨット・石取りの遊び方。どれかは `docs/ゲームの作りと実測.md`）。
  なしのときの局面や乱数の使い方を変えると、そこで落ちる。
