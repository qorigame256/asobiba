## Claude が決めた作り（本人に説明済み・変えるなら本人に確認）

- パーティーゲーム5つの作り（細かい決めごと・点数・時間は各ファイルの先頭）:
  - 石取りの山は15〜30個（毎回ばらばら）。3人以上で「最後を取った人の負け」は、負けが1人だけ。
  - 旗揚げは2〜10人。毎問、旗は前のお題の正しい形から始まる（前の問題で間違えても引きずらない）。制限時間は詳細設定（2〜4秒）。
  - 難読漢字は2〜10人。何度でも答え直せ、誰かが正解したら1.5秒待って締め切る。制限時間は詳細設定（15〜40秒）。
  - 的の早押しは2〜10人。大きい的1点・中2点・小3点・金5点・ドクロ −2点。「的が無いときに押すと −1点」は
    **画面に的が1つも出ていないときだけ**にした（的があるときに外れた所を押しても減点しない。スマホの押し損じで減らないように）。
    時間は詳細設定（20〜45秒）、ドクロは詳細設定で外せる。
  - ウミガメのスープは2〜10人。「パス」と、出題者の「答えを明かして終わる」を足した。出題者は、これまで出題者をした回数が
    いちばん少ない人（同じ顔ぶれで続けたときに引き継ぐ）。
  - ヨットは2〜10人（細かい決めごとと役の点は `yacht.js` の先頭）。役はよくある12種類（1〜6・チョイス・フォーダイス・フルハウス・S／Bストレート・ヨット）と、
    1〜6の合計63点以上でボーナス35点。全員が点を書くまで次の回へ進まない。サイコロの目は対局の種から作る（開発用の道具を使えば先の目が分かるのは、手札と同じ簡易の隠し方）。
    自分の手と次の回へ進むときだけ音を鳴らす（ほかの人の分まで鳴らすとにぎやかすぎるため）。CPU は少し気まぐれに役を選んで弱めている。
  - **ヨットの「2回目のヨット」**（2026-10-06 本人の決定。Claude が出した案から本人が選んだ）: 詳細設定で選べる（最初はなし）。ヨットの役に50点を書いたあとで、
    もう一度5個そろえてほかの役に書くと、そのたびに +100点。好きな役に書ける特別な決まり（ジョーカー）は入れない（Claude の判断。分かりやすさのため）。
  - ワードウルフは3〜10人（細かい決めごとは `wordwolf.js` の先頭）。ウルフは1人。話し合いの時間は詳細設定で 2／3（最初）／5分、だれでも「投票へ」を押して早められる。
    同じ票数で並んだら並んだ人だけで1回やり直し、それでも並んだらウルフの勝ち。ウルフの答えは、ひらがなにそろえて同じなら自動で正解、
    違えば多数派の人が「正解／ちがう」を押す（先に押した人の判定）。お題は Claude が作った90組（`wordwolf-data.js`）。

- せりあい（細かい決めごとは `seri.js` の先頭）: 持ち越した札がたまったら、いちばん新しい札の向きで決めて全部まとめて取る。最後に持ち越した札は誰も取らない。
  CPU は札の大きさに見合う強さの札を、ぶれを足して選ぶ（全員が15に集まって打ち消し合ってばかりにならないよう、上の方で散らしている）。
- お絵描き当て（細かい決めごとは `oekaki.js` の先頭）: 点は 1番 10点・2番 8点・3番 6点・それより後 5点、描いた人は当てた人1人につき3点。
  答えを見せる時間は5秒。描く人は「あきらめる」で早く終われ、部屋を出た描く人の回はすぐ終わる。お題は Claude が作った118個（`oekaki-data.js`。描きやすいものだけ）。
- ぴったりストップ（細かい決めごとは `pittari.js` の先頭）: 目標の秒数を5秒過ぎたら押せない。全員押したらすぐ結果へ。詳細設定で「いつも10秒」も選べる。
  CPU は押す時刻を先に決めて、その値を送る。
- タイピング早打ち（細かい決めごとは `typing.js` の先頭）: 正しく打てた時点で自動で送る（送るのは正解だけ。まちがいは手元で知らせる）。
  打った分だけ読みを緑にする。制限時間は 8秒＋読み1文字0.8秒 に詳細設定の倍率（短め0.7・ふつう1・長め1.5）。
  全員か3人が正解したら1.5秒待って締め切る。CPU は85%の確率で、読み1文字0.45〜0.7秒の速さで打ち終わる。お題は Claude が作った94個（`typing-data.js`）。
- 記憶リレー（細かい決めごとは `kioku.js` の先頭）: 2〜10人。4色（赤・青・黄・緑）。3個から1つずつ長くなり、最長30個。光るのは1つ0.7秒おき。
  押す時間は 4秒＋1個0.8秒。時間切れも間違いと同じ。点は「覚えられた一番長い数」。残っていた全員が同じ回で脱落したら同点で1位。
  押した順番そのものを手（`keys`）として送り、正しいかは全員の端末で確かめる（間違えたらその時点で送る）。光る順番は各自の端末で画面に出てから流すので、
  遅れて届いた端末でも見せ終わるまでは押せない。CPU は長いほど間違えやすい（3個で3%・5個16%・7個32%・9個48%）。40局で勝った CPU の平均は8.3個。

## 壊しやすい所・注意

- 難読漢字とウミガメの入力欄は、描き直しのたびに作り直さない（作り直すとスマホのキーボードが閉じ、打ちかけの文字が消える）。
  同じ場面のうちは入力欄を残して、ほかの所だけ差し替えている。タイピング早打ちも同じ。ワードウルフの「みんなのお題」の入力欄も同じ（`wordwolf.js` の `ui`）。
  お絵描き当ては絵（canvas）も残す（描き直すたびに作り直すと、描いている途中の線が消える）。1回ごとに1度だけ作り、新しい線だけを描き足す（`oekaki.js` の `ui` と `paint`）。
- お絵描き当ての線は手の一覧に入り、毎回まるごと送られる。送る量を小さくするため、座標は 0〜999 を2文字ずつに縮め、近すぎる点は捨て、0.5秒ごとにまとめて送っている。
  10人で描きまくっても1対局で数十 KB の見込み（実測はしていない）。区切りを細かくしたり座標を細かくしたりすると、送る量が増える。
