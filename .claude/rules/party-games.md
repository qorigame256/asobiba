## 石取り

- **石取り**: 自分の番に、山から石を取る。**最後の1個を取った人の負け。** 2〜6人が順番に。詳細設定で「最後を取った人の勝ち」も選べる。
  **山は1つだけ。1回に取れる最大数は対局の始めに3〜5個から決め、その対局の間はずっと同じ**（2026-10-03 本人の決定。
  前は「山3〜5つ・1つの山から好きな数」が最初で、「山1つ・1回に1〜3個」も選べた）。
- 石取りの山は15〜30個（毎回ばらばら）。3人以上で「最後を取った人の負け」は、負けが1人だけ。
- **石取りの表示**（2026-10-04 本人の希望）: 直前の人が取った石を色付きで残す（次の人が取るまで）。
- **石取りの「1回に取れる数」**（2026-10-06 の3回目の案）: 詳細設定で おまかせ（最初。今と同じく毎回3〜5個のどれか）／3個まで／4個まで／5個まで。
  （2026-10-03 に外した「1〜3個に決める」選択肢を、おまかせを最初にした形で戻すことを本人が選んだ。Claude は今のままを推した）
- **石取りの「取った数で勝負」**（2026-10-07 の15回目の案）: 詳細設定「最後の1個」に3つ目の選択肢として足し、名前を「勝ち負け」（最後の1個で負け（最初）／最後の1個で勝ち／取った数で勝負）に変えた。
  **鍵と値（`last`・`lose`・`win`）は前のまま**で、足した値は `count`（前の部屋の設定がそのまま使えるように）。山がなくなったとき取った石の合計がいちばん多い人の勝ち（同じ数なら同着で全員勝ち）。
  取った数は名前の下に出す。おまかせでは3つから抽選する。
- **石取りの「残りを隠す」**（2026-10-07 の17回目の案）: 詳細設定で なし（最初）・あり（key は `hide`）。決着するまで山の残りの数を見せない（「？」の山。直前に取られた石と、これまでに取られた数は出す）。
  取る数は 1〜最大数のボタンで選ぶ（残りが少なくても減らさない。減ると残りが分かるため）。**残りより多い数を選んだら、残りを全部取る**（Claude の判断。反則にして弾くと、弾かれたことで残りの数が分かってしまうため）。
  決着したら山を全部見せる。勝ち負け3つ・1回に取れる数と一緒に使え、取った数で勝負では実際に取った数を数える。CPU は今のまま（残りより多くは取らない）。おまかせで抽選する。
- **石取りの「山の数」**（2026-10-07 の19回目の案）: 詳細設定「山の数」（key は `heaps`）で 1つ（最初）・3つ。3つでは山は **3・5・7個**（昔からのニム）で、自分の番に **1つの山から1個以上、その山の全部まで**取れる。勝ち負け3つ・2〜6人はそのまま。
  **「1回に取れる数」は使わない。ただし取った数で勝負のときだけは使う**（使わないと、いちばん大きい山を丸ごと取るだけで決まってしまうため）。
  **残りを隠すと一緒のときは、山の大きさを種から 2〜5・4〜7・6〜9個で決める**（3・5・7 のままだと残りが分かってしまうため）。山ごとに「？」で出し、**空になった山は「なし」と見せる**（見せないと空の山を選んで番をむだにするため）。
  数のボタンはその山がいちばん大きい場合の数まで出し、残りより多い数を選んだらその山の残りを全部取る。おまかせで抽選する。

## 旗揚げ

- **旗揚げ**: お題（「赤上げて」「白下げないで赤下げない」など）が文字で出て、全員同時に赤白の旗のボタンで形を作る。
  15問（2026-10-04 本人の決定。前は10問）、正解した人に速い順で点、間違いは0点。
  **後半ほど難しく点も高い**（本人の希望。3段階の分け方は Claude の推奨を本人が承認）: 1〜5問目はそのまま、6〜10問目は制限時間8割・点2倍、
  11〜15問目は制限時間65%・点3倍で、命令を3つつなげた長いお題も出る（長いお題は読む分0.8秒足す）。お題の読み上げ（ブラウザの機能）は詳細設定でオンにできる。
- 旗揚げは2〜10人。毎問、旗は前のお題の正しい形から始まる（前の問題で間違えても引きずらない）。制限時間は詳細設定（2〜4秒）。
- **旗揚げの「黄色い旗」**（2026-10-06 の9回目の案）: 詳細設定で なし（最初）・あり。赤・白に黄色の旗が増え、お題にも黄色が入る。3本の旗の形がお題どおりかで正解を決める。
  点・段階・読み上げは今と同じ。3本ぶん操作が増えるので制限時間に0.5秒足す。おまかせで抽選する。
- **旗揚げの「あまのじゃく」**（2026-10-07 の13回目の案）: 詳細設定で なし（最初）・いつも・ときどき。お題と逆の形を正解にする。**逆にするのは「〜て」の命令だけ**（「赤上げて」なら赤を下げる）で、
  **「〜ないで・〜ない」は逆でもいつもどおり動かさない**（Claude の判断。「上げ」と「下げ」を入れかえるだけと覚えればよいため）。長いお題もそれぞれの「〜て」を逆にする。次の問題は逆にした正しい形から始まる。
  いつもは全部のお題、ときどきは15問のうち5問に「👿 あまのじゃく！」の印を付けてそのお題だけ逆にし（全員同じ）、印のお題だけ0.7秒時間を足す。読み上げがオンなら印のお題は「あまのじゃく！」と先に読む。
  黄色い旗と一緒に使える。おまかせで抽選する。
- **旗揚げの「まちがえたら脱落」**（2026-10-22 の27回目の案。key は `out`。分かれ目は Claude が決めた）: 詳細設定で なし（最初）・あり。答え合わせでまちがえた人（動かすお題で動かさなかった人も）はその場で脱落し、もう旗を動かせない。
  **残った全員がまちがえた問題では、だれも脱落しない**（全員いなくなって決着しないのを防ぐ）。残りが1人になったら次へ進むときに終わり、その人の勝ち（点が少なくても）。
  15問のあとに何人か残っていたら、残った人の中で点の多い人の勝ち（点の付け方は今までどおり）。CPU も脱落する。黄色い旗・あまのじゃくと一緒に使える。おまかせで抽選する。

## 難読漢字

- **難読漢字の読み当て**: 全員に同じ漢字が出て、ひらがなで打ち込む。いちばん先に正解した人に1点、10問。
  問題は Claude が200語ほど作る（読みが複数あればどれでも正解）。詳細設定で難しさを選ぶ。読みの誤りに気づいたら本人が知らせる。
- 難読漢字は2〜10人。何度でも答え直せ、誰かが正解したら1.5秒待って締め切る。制限時間は詳細設定（15〜40秒）。
- **難読漢字の「ヒント」**（2026-10-06 の5回目の案）: 詳細設定で なし（最初）・あり。
  制限時間の4割（25秒なら10秒）がたつと、読みの1文字目を見せる（Claude の判断。案では「10秒」と言ったが、15秒の制限時間でも間に合うよう割合にした）。
  待合室のおまかせでは抽選しない（`main.js` の `KEEP_KEYS` の hint。神経衰弱のヒントと同じ鍵）。
- **難読漢字の「答え方」（4つから選ぶ）**（2026-10-06 の9回目の案）: 詳細設定で 打ち込む（最初）・4つから選ぶ。選ぶときは入力欄を出さず、4つの読みのボタンから1つ押す。まちがいの3つは同じ難しさのほかの問題の読みから選ぶ（全員同じ）。
  **1問に1回だけ答えられる**。ほかの人の×は答えを見せる場面でだけ見える。点・速さの比べ方・制限時間・ヒントは今と同じ。
  誰かが正解したら1.5秒で締め切るのは今と同じで、**全員が答えたら（正解がいなくても）1.5秒で締め切る**（打ち込むは何度でも答え直せるので、今までどおり締め切らない）。おまかせでは抽選しない（`KEEP_KEYS` の choice）。
- **難読漢字の「問題の数」**（2026-10-07 の16回目の案）: 詳細設定「問題の数」（key は `rounds`）で 10問（最初）・15問・20問。同じ問題は出さない。問題が足りない難しさでは出せる数までにして一言出す。おまかせでは抽選しない（`KEEP_KEYS` の rounds）。
- **難読漢字の「ふりかえり」**（2026-10-07 の17回目の案）: 詳細設定にせず、いつも出す（見せるだけ。手・点は変えない）。対局が終わった画面に、出た漢字と正しい読み・自分の正誤・いちばん速く正解した人を出す。

## 的の早押し

- **的の早押し**（オリジナル）: **的が一度にいくつも次々に出て**、それぞれ一番早く押した人の点（本人指定）。
  **点数の違う的を混ぜる**（小さい的は高い点など。本人指定）。押してはいけない的・的が無いときに押すと減点。
- 的の早押しは2〜10人。大きい的1点・中2点・小3点・金5点・ドクロ −2点。「的が無いときに押すと −1点」は
  **画面に的が1つも出ていないときだけ**にした（的があるときに外れた所を押しても減点しない。スマホの押し損じで減らないように）。
  時間は詳細設定（20〜45秒）、ドクロは詳細設定で外せる。
- **的の早押し**（2026-10-04 本人の希望）: 人数が多くても画面が動かないよう、点数の札は1行（入りきらない分は札の列だけ横に動かせる）にし、
  的が出ている間はページを動かさない。的の場は画面の高さに収まる大きさにする（`targets.js` の `fit`）。
- **的の早押しの「動く的」**（2026-10-06 の6回目の案）: 詳細設定で なし（最初）・あり。的が出ている間ゆっくり動き、ふちで跳ね返る（全員同じ動き）。見た目だけで手は変わらない。CPU の反応は少し遅くした。
- **的の早押しの「小さい的は高い点」**（2026-10-07 の11回目の案）: 詳細設定で なし（最初）・あり。**的はもとから大きさと点が違う**（赤 大きい1点・青 中2点・紫 小3点・金5点）ので、ありでは**赤と青の的がそれぞれ3つの大きさで出る**
  （大きい＝今と同じ点・中くらい2倍・小さい3倍。出る割合は 大4割・中3割・小3割）。紫と金はこれより小さくするとスマホで押しにくいので変えない。ドクロも変えない（小さくしても避けやすくなるだけのため）。
  動く的・ドクロと一緒に使える。おまかせで抽選する。

## ウミガメのスープ

- **ウミガメのスープ**: 部屋の1人が出題者（1問ごとに交代）。ほかの人は順番に、自分の番で「質問」か「解答」のどちらか1つ。
  出題者は「はい・いいえ・関係ない」で答え、解答の正誤も決める。外しても続けられ、いちばん先に当てた人の勝ち。
  問題は Claude が作るオリジナル問題集（30問ほど）から選ぶか、出題者が書く。**CPU は入れられない**（質問や判定ができないため。
  AI に答えさせるのは有料）**ので、人間2人以上が要る。**（2026-10-26 に、言葉の手がかりで答える CPU の出題者を足した。下の「2026-10-26 本人の依頼」）
- ウミガメのスープは2〜10人。「パス」と、出題者の「答えを明かして終わる」を足した。出題者は、これまで出題者をした回数が
  いちばん少ない人（同じ顔ぶれで続けたときに引き継ぐ）。
- **ウミガメのスープの「質問の数」**（2026-10-06 の6回目の案）: 決めない（最初）・20回・30回。全員で合わせた回数で、**数えるのは出題者が答えた質問だけ**（解答・パスは数えない）。
  使い切ったら、**回答者が1人1回ずつ順に最後の解答**をして、だれも当てられなければ**出題者の勝ち**（最後の解答は、最後の質問をした人以外が解答できないまま終わらないように Claude が足した）。
- **ウミガメのスープの「部分的にはい」**（2026-10-07 の21回目の案。key は `partial`）: なし・あり（2026-10-26 から最初は あり。本人の依頼）。出題者の答えに「部分的にはい」を足す。質問の数にはほかの答えと同じく1回と数える。おまかせで抽選する。
- **ウミガメのスープの「制限時間」**（2026-10-22 の27回目の案。key は `time`。分かれ目は Claude が決めた）: 決めない（最初）・5分・10分。問題が決まってからその時間がたったら、
  **質問を使い切ったときと同じく、回答者が1人1回ずつ最後の解答**をして、だれも当てられなければ出題者の勝ち。返事待ちの質問・判定待ちの解答があれば、それを片付けてから最後の解答に入る。
  質問の数と一緒に使え、先に来た方で最後の解答に入る。時間はホストの端末が計る（ホストが再読み込みすると計り直し）。残り時間は各端末で問題が出た時から数えて出す（少しずれる）。
  おまかせでは抽選しない（`KEEP_KEYS` の time）。

## 壊しやすい所・注意

- 難読漢字とウミガメの入力欄は、描き直しのたびに作り直さない（作り直すとスマホのキーボードが閉じ、打ちかけの文字が消える）。
  同じ場面のうちは入力欄を残して、ほかの所だけ差し替えている。タイピング早打ちも同じ。ワードウルフの「みんなのお題」の入力欄も同じ（`wordwolf.js` の `ui`）。人狼の話す欄も同じ（`jinro.js` の `ui`。昼でないときは隠すだけ）。
  お絵描き当ては絵（canvas）も残す（描き直すたびに作り直すと、描いている途中の線が消える）。1回ごとに1度だけ作り、新しい線だけを描き足す（`oekaki.js` の `ui` と `paint`）。
- 10を作れの問題の一覧は `make10-data.js`（`tools/make-make10.mjs` が作る。手で直さない）。画面で毎回計算すると0.5秒ほど止まるので前もって書き出している。
  **`make10.js` の計算（`solveAll`・`trim`）を変えたら作り直す**（`tools/test-logic.mjs` が、書き出したものと計算し直したものが同じかを見ている）。
- 10を作れの式を組む欄と、以心伝心の入力欄も、同じ場面のうちは作り直さない（組みかけの式・打ちかけの文字が消えないように。各ファイルの `ui`）。
- お絵描き当ての線は手の一覧に入り、毎回まるごと送られる。送る量を小さくするため、座標は 0〜999 を2文字ずつに縮め、近すぎる点は捨て、0.5秒ごとにまとめて送っている。
  10人で描きまくっても1対局で数十 KB の見込み（実測はしていない）。区切りを細かくしたり座標を細かくしたりすると、送る量が増える。
- お絵描き当てのインクの長さは整数の座標から `Math.sqrt` で数えて丸める（**`Math.hypot` を使わない**。端末で末尾がずれると同期が崩れるため）。
- 遊び方を足したとき、なし（最初の値）のときの局面の形と乱数の使い方を前と全く同じにしてあり、`tools/test-logic.mjs` が前の作りで取った指紋と比べているものが多い
  （旗揚げ・的の早押し・お絵描き当て・難読漢字・ぴったりストップ・ヨット・石取りの遊び方。どれかは `docs/ゲームの作りと実測.md`）。
  なしのときの局面や乱数の使い方を変えると、そこで落ちる。

  ほかの人の正解は pop の音。**1回の入力で3文字以上増えたら予測変換（候補から選んだ）と見て戻す**（`typing.js` の `PREDICT_JUMP`。ふつうに打つと1回に1〜2文字、漢字に変換すると減るので引っかからない。貼り付けも戻る）。
- **的の早押し**: ホストが圧倒的に有利（本人の声）。
  Claude の判断: 原因は、だれかが押した知らせが届くとすぐ的を消していたこと（ゲストの画面では、ホストが押した的が出てすぐ消えて押す機会が無かった）。
  ほかの人が押した的も、自分の画面で的が出てからその人の時間（best.ms）がたつまでは残す（`targets.js` の `loop` の `lost`）。速さは各自の画面で比べるので、残っている間に押せば取り返せる。
- **旗揚げ**: ほかの人の旗も見えるように。Claude の判断: 自分の旗の下に、ほかの人の名前と小さな旗（いまの形・答え合わせでは ○ が緑・× が赤の枠）を並べる。
  答えの途中も見える（実際の旗揚げでも見えるので。まねると遅くなるので点は取りにくい）。送るものは増やしていない（答えは手の一覧で全員に届いている）。
- **ウミガメのスープ**: CPU も出題者になれる・部分的にはいを最初に・前の はい／いいえ／関係ありません を直せる・各人の考えた時間を出す・出題者を選べる。
  本人の決定: CPU は AI ではなく「言葉の手がかりで答える」簡単なもの（AI はサーバーと費用が要ると伝えて、本人が選んだ）。
  Claude の判断: 詳細設定「出題者」（key `setter`。人（順番に交代。最初）／CPU）。CPU にすると CPU が1人だけ入って出題者になる（ゲームの `fixedCpus`。`main.js` の `lineup`。CPU の席は `init` の `cpus`）。
  CPU の出題者は、手がかりを書いた14問（`umigame-data.js` の `CPU_KEYS`）からくじで選ぶ。質問に「はい」の言葉があれば はい、「いいえ」の言葉があれば いいえ、両方なら部分的にはい（なしなら はい）、
  どちらも無ければ 関係ありません。「〜ない？」「〜ませんか？」で終わる質問は はい・いいえを入れ替える。解答は手がかりの言葉の組が全部入っていれば正解。
  CPU が出題者のときは、回答者も自分の番に「降参して答えを見る」ができる（CPU は答えを明かさないので）。
  答えを直す: 出題者（人）は、やりとりの欄の各質問の横の「直す」で答えを替えられる（「（直した）」と出る。質問の数は変わらない）。
  出題者を選ぶ: 問題を選ぶ前に、出題者が「出題者を代わる…」でほかの人に渡せる（CPU の席には渡さない）。
  考えた時間: 各人の札に「⏱ いまの秒数（計 合計）」。各端末が局面の変わった時刻で数える（手に時刻は入れられないため。再読み込みすると0から）。
