## リバーシ

- **3〜4人のリバーシ**（2026-10-04 本人の決定。どれも Claude の推奨を本人が承認）: 市販の「ローリット」に近いルールにする。
  はさむ石は相手なら誰の色でも（色が混ざっていても）よく、はさんだ石は全部自分の色になる。はさめる所があれば必ずそこに置き、
  どこにも無いときはパスせず、石のとなりの空いたマスならどこにでも置ける。盤が埋まったら終わりで、石がいちばん多い人の勝ち。
  **詳細設定「人数」（2〜4人）で選ぶ**（マルバツ・コネクトフォーと同じ）。2人のときは今までのルールのまま。
  Claude が決めたこと（数字は `reversi.js` の `START` の上）: 盤は 8×8 のままで大きさは選べない。石は 黒・白・赤・青。
  最初の石は真ん中の4マスで、3人は赤を2つ、4人は1色1つずつ。盤が埋まるまで打つので最後の1手を打つ人が有利になりやすく、
  並べ方を変えても席順の差は1割ほど残った（もう一回で打つ順番が回るのでならされる）。いちばん多い人が2人以上なら引き分け。
  CPU は読みをせず、置いた後の石の点数で選び、ふつうは次の人・つよいはほかの全員に隅を渡す手を避ける。
- **リバーシの「盤の大きさ」**（2026-10-06 本人の決定。Claude が出した案から本人が選び、2人だけにするのは Claude の推奨を本人が承認）:
  詳細設定で 8×8（最初）・6×6・10×10。**2人のときだけ**（3〜4人の最初の石の並べ方と席順の差は 8×8 で測ったものなので、3〜4人はいつも 8×8）。
  Claude が決めたこと: 最初の石はどの大きさでも真ん中の4マス。CPU の石の点は 8×8 の表と同じ考え方で端からの距離で付ける（8×8 では前の表と全く同じ）。
- **リバーシの「四隅封印」**（2026-10-06 の他の AI の案）: 四隅に置けない（隅だけ。まわりは封じない）。
  2〜4人・どの盤の大きさでも使える。3〜4人は隅を残して埋まったら終わり。
- **リバーシの「穴あき盤」**（2026-10-06 の5回目の案。分かれ目は「おすすめどおり」と言われたので Claude が決めた）:
  詳細設定で なし（最初）・あり。石を置けないマス（穴）が数か所あり、置き場所は毎回変わる。人数・盤の大きさ・四隅封印と一緒に使える。
  穴は 6×6 で2つ・8×8 で4つ・10×10 で6つ。盤の真ん中を中心に**点対称**に置く（先手と後手で不公平にならないように）。
  隅と真ん中の 4×4 には置かない。
- **リバーシの「角でもう1手」**（2026-10-07 の16回目の案）:
  詳細設定で なし（最初。今と同じ）・あり（鍵は `corner`。四隅封印の `corners` とは別）。四隅のどれかに置いたら、同じ人が続けてもう1回置く（続けて置いた手がまた角なら、さらにもう1回）。
  続けて置く番に置ける所が無ければ、ふつうに次の人へ（パスと同じ。2人で両方とも置けなければ終局）。状態の欄に「黒は角を取ったので、もう1回！」、置けなかったときは
  「角を取りましたが、続けて置ける場所がないので白の番です」と出す。2人・3〜4人の両方で効き、3〜4人の「置ける所」はいつもと同じ（はさめなければ石のとなり）なので、
  盤が埋まっていなければ必ず続けて置ける（最後の1マスが角なら、そのまま終わり）。盤の大きさ・穴あき盤と一緒に使える。四隅封印と一緒では角に置けないので効かない（詳細設定の説明に書いた）。
- **リバーシの「石の数を隠す」**（2026-10-07 の19回目の案。分かれ目は「おすすめどおり」と言われたので Claude が決めた）:
  詳細設定で なし（最初。今と同じ）・あり（鍵は `hide`）。対局の間は状態の欄に石の数（「黒 2 − 2 白」・3〜4人の各色の数）を出さず、代わりに「石の数はひみつ（終わったら出ます）」と出す。
  盤はいつもどおり見えるので、自分で数えるのは自由。終わったら（局面の `over`）いつもどおり数を出す。ほかの決まり・CPU は変えない。人数・盤の大きさ・四隅封印・穴あき盤・角でもう1手と一緒に使える。
  遊び方なので、おまかせで抽選する（`KEEP_KEYS` に入れない）。

## 五目並べ

- 五目並べ（細かい決めごとは `gomoku.js` の先頭）: 最初は禁じ手なし・6つ以上並んでも勝ち（禁じ手は詳細設定。下の「禁じ手」）。盤は詳細設定で 15路（最初）か 13路（スマホで押しやすい）。

  両者とも同じ（連珠の黒だけの禁じ手とは違う）。

  - はさみ取り: 相手の石が**ちょうど2つ**並んだ両側を自分の石ではさむと取れる。**5組（10個）取っても勝ち**。「ぴったり五目」と同時に使える（別々の設定）。
    自分から、はさまれる形に置いても取られない。取られた点にはまた置ける。
- **五目並べの「禁じ手」**（2026-10-06 の3回目の案）: **正式な連珠どおり**、先手の黒だけ三三・四四・6つ以上並べるのを禁止
  （本人の選択。Claude の推奨）。**禁じ手の点は押せないようにして印を出す**（正式には置いたら負けだが、知らずに負けないように。Claude の推奨を本人が承認）。
- **五目並べの「じゃま石」**（2026-10-07 の17回目の案。分かれ目は「おすすめどおり」と言われたので Claude が決めた）:
  詳細設定で なし（最初。今と同じ）・あり（鍵は `blocks`。ほかの五目並べの設定と同じ true/false）。始める前に、だれの物でもない灰色のしま模様の石を **15路で6個・13路で5個** 置く。
  じゃま石には置けず、並びはそこで切れる（だれの石でもない）。置き場所は対局の種（`init` の `seed`。コネクトフォーのじゃま石と同じ）から `blockers` が決めるので、全員の端末で同じ・毎回ちがう。
  盤の一番外の線と、天元から2マス以内（真ん中の 5×5）には置かない。じゃま石どうしは縦・横・ななめに2マス以上あける（並ばない・固まらない）。
  はさみ取りでは取れず、はさむ石にもならない。禁じ手では盤の外と同じに見る（じゃま石で止まった3つ並びは「三」にならない）。ぴったり五目・盤の大きさとも一緒に使える。

## 壊しやすい所・注意

- じゃま石（コネクトフォー・五目並べ）・穴あき盤・金の四角の置き場所は、対局の種から決める。そのため**盤のゲームの `init` に `seed` を渡すようにした**（`main.js` の `replay`。
  同じ画面の2人も始めるたび・もう一回のたびに種を作り直す）。待った・ふりかえりは種から当て直すので、同じ場所に出る。
- はさみ将棋: **同じ局面の数え方はゾブリストハッシュ（マスと駒ごとの乱数の XOR）で、動いた駒と取った駒の分だけ足し引きする。** 盤を文字にして比べたら つよい の1手が1秒かかった。
  足し引きを間違えると引き分けの判定がずれるので、自動確認で「盤から作り直した目印と同じ」かを毎手見ている（`hashOf`）。
- マンカラ: 3人の CPU は `boardCpu` を使わない（2人用の読みなので、3人では「ふつう」が「よわい」に 2勝58敗と逆になった）。
- 海戦ゲーム: CPU は自分が撃った結果だけを見て選ぶ（相手の配置はのぞかない）。全員の端末が相手の船を知っている作りなので、CPU の中で相手の配置を見ないこと。
  `style.css` の `.ks-grid` は10列の決め打ちなので、列の数は `kaisen.js` が盤ごとに `grid-template-columns` で書き換える。
- 詳細設定の鍵がぶつからないようにしてある: マンカラの穴の数の鍵は `pits`（リバーシの穴あき盤の鍵 `holes` とぶつからないように）。リバーシの角でもう1手は `corner`、四隅封印は `corners`。
- CPU の強さの順は `tools/test-cpu.mjs` が毎回見ている（運でときどき落ちるものは CLAUDE.md の「ファイル」の `test-cpu.mjs`）。遊び方を足して強さの差が変わったら、そこで分かる。
