## Claude が決めた作り（本人に説明済み・変えるなら本人に確認）

- エアホッケーの作り（数字は `hockey.js` の先頭）: 盤は縦長（横1：縦1.6）、ゴールは横幅の36%。点を取られた側の陣地から始める。
  自分は常に画面の下側（オンラインの青は盤を上下逆さに見る）。同じ画面の2人は、画面の上半分と下半分に触れた指でそれぞれ動かす。
  オンライン（試作）は、パックが自分の陣地にある人がパックの動きを計算して送り、真ん中の線を越えたら相手に担当を渡す
  （打つ感触に自分の側の遅れが乗らないように）。相手の陣地のパックは届いた位置を遅れの半分だけ先へ進めて描く。
  点は決められた側（パックの担当）が知らせる。待合室は盤のゲームと同じだが、2人のときは CPU を選べず、人2人がそろうまで始められない。
- 3人の作り（2026-10-05）: 六角形は中心から角まで 0.83、ゴールの幅 0.38（数字は `hockey.js` の先頭）。陣地は中心から見た扇形で、
  両隣の壁の半分ずつを含む。自分のゴールが常に画面の下に来るよう盤を回して描く。盤の形ごとの関数は「台」（`table` で作る。ゴールの幅も台が持つ）にまとめ、
  動かし方と同期は台の関数だけを使う。台の `step` は**入れられた席**を返す（2人の `stepPuck` だけは古い形のまま「点を取った側」を返す）。
  3人の CPU は2人と同じ考え方で、打ち込む先はゴールの前から離れている相手（ときどき逆）。オンラインの CPU の強さは詳細設定（最初は「よわい」）。
- オンラインで CPU の席と**部屋を出た人の席**はホストの端末が CPU として動かす（`main.js` の `cpuSeats`）。2人のオンラインでも、
  ゲストが部屋を出るとその席を CPU が引き継ぐ（3人の作りに合わせて変わった。前は止まっていた）。送る中身には、その端末が動かしている席（`c`）を付け、
  観戦中のホストが CPU を動かしても受け手が見分けられるようにしている（送った人の席の番号では、観戦中のホストが -1 になるため）。
- パック2つの作り（2026-10-06）: 最初は席0と席1の陣地に1つずつ。パックどうしもぶつかる（同じ重さ。壁より先に見る）。オンラインでは、
  両方のパックを同じ端末が動かしているときだけぶつけ、片方がほかの端末ならすり抜ける。CPU は自分の陣地にあるパック（その中ではゴールに近い方）を追う。
  オンラインの持ち主はパックごと（`owners`）。**点数は席ごとの失点（`st.lost`）で合わせる**: 席 c の失点を増やすのは席 c を動かす端末だけで、
  ゴールの知らせと毎回の位置の知らせの両方に失点を付け、受け手は大きい方を取る（`mergeLost`）。前のように「ゴールの回数（ep）」で合わせると、
  パック2つで別々の端末がほぼ同時に決めたとき片方が消えて点数が食い違うため。`ep` は「もう一回」の回数だけになった（パック1つでも同じ作り）。
  ブラウザの中で偽の通信（遅れ 60〜100ms）で3台つないで確かめた。CPU どうしでは、パック2つの1点はパック1つのおよそ3分の1の時間で入った。
- マレットの大きさの作り（2026-10-08）: 半径は台（`table` の4つ目の引数 `malletKey`）が `rm` として持ち、当たり（`stepPuck`・`stepHex`）・動ける範囲（`clampMallet`・`clampHex`。
  3人の範囲は半径ごとに1回だけ作って覚える `limitsOf`）・じゃまブロックからの押し出し・CPU の下がる位置・描く大きさが全部 `rm` を使う。ふつうの台は前と同じ関数そのもの
  （自動確認で同じ動きを見ている）。オンラインも詳細設定から台を作るので、どの端末も同じ大きさで当たりを計算する（パックの持ち主の作りは変えていない）。
  **大きいマレットだと、真ん中の線の近くで横の壁ぎわの遅いパックを CPU 2人が両側から押さえつけて何分も動かなくなった**（CPU どうしで 20分決着しない試合が出た）。
  そのため大きいときだけ、遅いパック（0.4 より遅い）にマレットがくっついていたら CPU は一度下がって打ち直す（`pinned`。2人・3人とも）。ふつう・小さいでは使わない（前と同じ動きにするため）。
  大きいマレットでも、止まって守るマレットがふさぐ幅（2×(0.098+0.042)=0.28）はふつうのゴールの口（0.36）より狭い。せまいゴール（0.27）とでは真正面はほぼふさがるが、ななめ・壁で跳ねた球は入る。
